# DWGToBundleTaskAddIn

Самостоятельное дополнение-задача SOLIDWORKS PDM (EPDM). Принимает задачу PDM на
сервере и для каждого DWG/DXF вызывает проверенный бандл `dwg2pdf.bat`
(accoreconsole → цветной PDF → Ghostscript `settransfer` → ч/б PDF), затем
возвращает итоговый PDF в архив: новый файл — через `IEdmBatchAdd`, существующий —
через разрегистрацию `LockFile` и регистрацию новой версии `UnlockFile`.

Отдельного «типа задачи DWGDXFToPDF» и движка DraftSight НЕ требуется:
дополнение само фильтрует выбор по расширениям `.dwg` / `.dxf`.

## Состав
- `DwgBundleAddIn.cs` — `IEdmAddIn5` (GUID `EFBE62F2-6ED8-4FA7-9975-49F92FBD6215`), хуки TaskRun/TaskSetup/TaskSetupButton.
- `TaskSettingsPage.cs` — страница настроек задачи (путь к `.bat`, accoreconsole, Ghostscript, шаблон пути PDF, таймаут, папка журнала). Методы `LoadData/StoreData` EPDM вызывает по IDispatch.
- `BundleTaskExecutor.cs` — приём задачи, актуальные версии, запуск `.bat`, возврат PDF в архив.
- `EngineExtractor.cs` — распаковывает встроенные в DLL `dwg2pdf.bat` + `SheetLayoutDistributor.dll` в отдельную папку версии `%AppData%\DWGToBundleTaskAddIn\engine\<MVID>\` перед запуском.
- `Resources\dwg2pdf.bat`, `Resources\SheetLayoutDistributor.dll` — движок, вшитый в сборку как вложенные ресурсы.
- `Callbacks.cs`, `Logger.cs`, `Properties/AssemblyInfo.cs`.
- `build.cmd` — офлайн-сборка через `csc.exe` (без SDK/NuGet); **работает и при политике PowerShell AllSigned** (cmd не подпадает под политику скриптов).
- `build.ps1` — то же на PowerShell (нужна разрешающая политика выполнения).
- `bin\DWGToBundleTaskAddIn.dll` — собранная сборка (net48), движок уже внутри.

Итого на сервер кладётся **один файл** `DWGToBundleTaskAddIn.dll` — бандл рядом не нужен.

## Регистрация COM (на машине, где крутится PDM Agent / где создаётся задача)
Запустите от администратора (путь к DLL должен быть постоянным, `/codebase`):
```
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\regasm.exe "D:\progs\DWGToBundleTaskAddIn\bin\DWGToBundleTaskAddIn.dll" /codebase
```
Удаление регистрации: тот же путь с `/unregister`.

## Куда положить аддин (один файл)
На машину PDM‑агента кладётся **только** `DWGToBundleTaskAddIn.dll` в постоянное место,
например `C:\PDM\DWGToBundleTaskAddIn\DWGToBundleTaskAddIn.dll`, и регистрируется оттуда:
```
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\regasm.exe "C:\PDM\DWGToBundleTaskAddIn\DWGToBundleTaskAddIn.dll" /codebase
```
Движок (`dwg2pdf.bat` + `SheetLayoutDistributor.dll`) **вшит в DLL** и при запуске задачи
распаковывается в `%AppData%\DWGToBundleTaskAddIn\engine\<MVID>\`. Класть рядом `.bat` или папку
`dwg2pdf_bundle\` **не нужно**. На машине по‑прежнему должны стоять AutoCAD
(accoreconsole) и Ghostscript — их в DLL вшить нельзя, это внешние программы.

> Можно переопределить движок, не пересобирая DLL: в задаче указать свой путь к `dwg2pdf.bat`
> или вставить тело `.bat` прямо в поле «Код сценария».


## Создание задачи в PDM Administration
1. Vault → Tasks → Add → тип **Custom Task** (Add-in), выбрать «DWG->PDF Bundle Task Add-in».
2. Откроется страница настроек:
   - **Путь к dwg2pdf.bat** — оставьте пустым: движок встроен в DLL (распаковывается в
     `%AppData%\DWGToBundleTaskAddIn\engine\<MVID>\`). Путь указывают только чтобы переопределить движок.
   - **accoreconsole.exe / gswin64c.exe** — можно оставить пустыми: тогда возьмутся из
     переменных окружения агента (`DWG2PDF_ACCORECONSOLE`, `DWG2PDF_GS`) либо из
     значений по умолчанию внутри `.bat`.
   - **Путь результата PDF** — задаётся **относительно корня хранилища**, к которому
     подключён аддин (локальный путь `IEdmVault.RootFolderPath` на этой машине).
     Например `\PDF\<FileName>новый` → `<корень_хранилища>\PDF\<Имя>новый.pdf`.
     Если ввести абсолютный путь (`C:\...` или `\\сервер\...`) — используется как есть.
     Поддерживаются `<SourceFolderPath> <FileName> <FileExt> <FileRev> <FileVer> <FileState> <RootFolder> <Date>` и `<%ПЕРЕМЕННАЯ%>` (переменная карточки).
     Папки хранилища по пути создаются автоматически (`AddFolderPath`).
   - **Таймаут, мин** — по умолчанию 25 (держим ниже лимита 30 мин хоста).
   - Существующий PDF обновляется новой версией. Старый параметр «Заменять существующий PDF» больше не действует.
   - **Папка журнала в архиве** — необязательно; туда кладётся `.txt`-отчёт по задаче.
3. Назначьте задачу на переход состояния или меню.

## Как работает возврат в архив
- Для каждого файла берётся актуальная версия (BatchGet), `.bat` запускается в
  РАБОЧЕЙ ПАПКЕ чертежа (чтобы разрешились внешние ссылки), промежуточный ч/б PDF
  бандл пишет с ASCII-именем `<папкаDWG>\<база>~mono.tmp.pdf`.
- Финальное имя (с кириллицей/префиксом) формирует только C#: временный PDF копируется
  в `%AppData%\DWGToBundleTaskAddIn\run-<guid>\<имя-результата>.pdf` и оттуда добавляется
  в архив по шаблону Output Path.
- Если PDF с таким именем уже в архиве: файл разрегистрируется, обновляется и регистрируется как новая версия. Прежняя версия сохраняется в истории.

## Диагноз: «PDF создался, но не зарегистрировался, задача с ошибкой»
Корень (исправлен): старый `dwg2pdf.bat` писал промежуточный PDF с кириллическим суффиксом
(«…новый.pdf»). `cmd` формирует это имя в OEM-кодировке консоли (CP866), а C-шарп искал файл по
корректному Unicode-имени → `File.Exists` возвращал false. PDF физически оставался в папке DWG,
но в архив не попадал, а задача падала. Сейчас промежуточное имя строго ASCII
(`<база>~mono.tmp.pdf`), кодировка консоли на поиск не влияет.
## Диагноз: «PDF пустой / 0 страниц» (истинная причина)
Пустой PDF порождает **не код возврата в архив, а плагин AutoCAD**. Для части чертежей
`SheetLayoutDistributor` не может настроить печать и пишет битый цветной PDF: в его логе
`[ERROR] Лист_N пропущен (нет PageSetup): eInvalidPlotInfo`, а Ghostscript на этом входе даёт
`Cannot find a 'startxref' / Trailer dictionary not found / No pages will be processed` и
итоговый ч/б PDF на 0 страниц (~2 КБ). Проверено: с `settransfer` и без — результат одинаковый,
т.е. флаги Ghostscript не при чём. В версии 1.0.1.0 аддин блокирует такие результаты перед добавлением в архив и записывает
`pdf=0` в карточку исходного DWG/DXF. Причину сбоя построения листов по-прежнему нужно
исправлять в плагине/AutoCAD; проверка аддина служит защитой от загрузки брака.

## Важно про сессию 0 (главный непроверенный сценарий)
`accoreconsole` с `NETLOAD` из служебной сессии PDM-агента может не подняться.
Если задача падает с кодом 124/1, а в `bat out` пусто:
- настроить PDM Agent на интерактивную сессию, либо
- обёртка `psexec -i`, либо
- Task Scheduler «запускать только при входе пользователя».
Диагностика: `%AppData%\DWGToBundleTaskAddIn\DWGToBundleTaskAddIn.log`
(строки `TaskRun start. bat=... | acc=... | gs=...`, `bat exit=...`, `bat out: ...`).

## Требования на целевой машине
- AutoCAD (accoreconsole) + Ghostscript (gswinXXc.exe) — внешние программы, должны быть
  установлены на машине агента (в DLL не вшиваются).
- .NET Framework 4.8. Сам движок (`dwg2pdf.bat` + `SheetLayoutDistributor.dll`) уже внутри DLL.
## Префикс результата (настраиваемый) и ручной запуск

**Префикс.** В настройках задачи есть поле «Префикс имени результата (<Prefix>)».
Оно подставляется в шаблон пути результата токеном `<Prefix>`. По умолчанию пусто,
поэтому имя PDF равно имени чертежа. Шаблон по умолчанию: `<SourceFolderPath>\<Prefix><FileName>`.
Префикс можно поставить в любое место шаблона (например суффиксом: `<FileName><Prefix>`).
Ранее зашитый суффикс «новый» убран — теперь это просто значение префикса, которое вводит пользователь.
Для уже созданных задач сохранившееся битое значение пути результата починится автоматически (RepairMojibake).

**Ручной запуск через контекстное меню.** После регистрации аддина в Windows Explorer
и в PDM у выбранных DWG/DXF появляется пункт «Конвертировать DWG в PDF». Он выполняет ту же
конвертацию и возврат в архив без перехода по статусу. ВАЖНО: у командного запуска нет экземпляра
задачи, поэтому он использует значения ПО УМОЛЧАНИЮ (движок из DLL, DefOutput/DefPrefix),
а не настройки конкретной задачи. Итог показывается в диалоге и в журнале `%AppData%\DWGToBundleTaskAddIn`.


## Проверка результата PDF — 1.0.1.0

Перед добавлением или заменой PDF аддин запускает Ghostscript с устройством `inkcov`
при 150 dpi, по видимой области CropBox. Проверяется фактическое покрытие каждой страницы
цветом, а не размер файла и не наличие текста. Проверка использует оставшееся время общего
таймаута конвертации одного DWG/DXF.

Результат не добавляется в PDM, если PDF отсутствует, имеет нулевой размер, не содержит
страниц, не читается Ghostscript, содержит хотя бы одну страницу с нулевым покрытием CMYK,
либо проверка не выполнена (например, отсутствует Ghostscript или истёк таймаут).
Ошибка самого конвертера тоже блокирует загрузку. Причина записывается в журнал и статус задачи.

При отказе аддин записывает **число 0 в переменную `pdf` исходного DWG/DXF**, во всех
его конфигурациях/листах карточки. После фиксации выполняется обратное чтение значений.
Успешная конвертация не меняет `pdf`. Перед повторной отправкой исходника значение
сбрасывает настроенный пользователем поток. Аддин не переводит файлы в другие состояния.
Задача с отклонённым результатом завершается с ошибкой, даже если запись `pdf=0` успешна.

### Настройка в PDM

- Переменная `pdf` должна существовать в карточке DWG/DXF; рекомендуемый тип — целое число.
- Включить «Без версии / Version free», предпочтительно «Последняя версия / Latest version».
- У пользователя, от имени которого выполняется задача, должны быть права «Изменять данные
  переменных без версии / Edit version free variable data» и на папку, и на состояние.
- Исходник должен быть зарегистрирован в архиве. Аддин не разрегистрирует DWG и
  не создаёт новую версию ради служебного флага.
- Если запись не удалась, PDF всё равно блокируется. В задаче будет отдельная ошибка
  «НЕ УДАЛОСЬ записать pdf=0». Сам факт отбраковки не выдаётся за успешную запись переменной.
- Проверять переменную в потоке нужно после завершения задачи: запуск задачи асинхронный.

Путь к Ghostscript для проверки: поле задачи → переменная окружения `DWG2PDF_GS` →
`C:\Program Files\PDFCreator\Ghostscript\bin\gswin32c.exe`. При своём bat/сценарии с другим
Ghostscript явно укажите этот путь в задаче или окружении. Проверка C# действует и для
пользовательского сценария, и для ручного запуска через меню.

### Сохранность и пределы проверки

Старый локальный `<имя DWG>.pdf` резервируется перед запуском конвертера и восстанавливается
после его завершения. Если восстановление не удалось, резервная копия остаётся в
`%AppData%\DWGToBundleTaskAddIn\pdf-recovery`; исходный путь и путь копии записываются в журнал.
Отклонённый результат не вызывает удаление/замену архивного PDF. Временные результаты разных
исходников имеют отдельные папки, даже если их итоговые имена совпадают.

`inkcov` округляет покрытие до пяти знаков. Очень мелкие одиночные отметки могут считаться
пустотой; нормальные линии и рамки проверяются как непустые. PDF с одной только рамкой,
штампом или ошибочным содержимым будет считаться непустым: смысл чертежа эта проверка
не анализирует. Отсутствующие в PDF листы также нельзя обнаружить без ожидаемого числа листов.

### Проверено при подготовке

## Безопасное сохранение результата — 1.0.2.0

После проверки PDF аддин удерживает блокировку на путь промежуточного PDF и путь результата
до завершения публикации. Если задача на том же компьютере уже обрабатывает этот путь,
вторая задача завершается с понятной ошибкой; `pdf=0` из-за занятости не ставится.
При неожиданном завершении процесса автоматический повтор откладывается: сначала
проверьте AutoCAD, Ghostscript и каталог `pdf-recovery`.

Для существующего PDF: PDM разрегистрирует тот же файл (`IEdmFile5.LockFile`), копирует
проверенное содержимое в его рабочую копию, регистрирует (`IEdmFile5.UnlockFile`)
как новую версию. `DeleteFile` не вызывается.
При ошибке до регистрации собственная разрегистрация отменяется (`UndoLockFile`); прежняя версия
остаётся в архиве. Если регистрация уже прошла, операция не откатывает опубликованную версию.

Для нового PDF: `BatchAdd` регистрирует файл; аддин проверяет результат `CommitAdd` и при
необходимости возвращает добавленный файл в архив. В обоих случаях загружается именно
сохранённая версия во временный путь и сравнивается SHA-256 с валидированным PDF.
Только после совпадения задача считает этот файл успешным. Если публикация не подтверждена,
задача сообщает ошибку; `pdf=0` ставится только при неудачной конвертации/проверке PDF,
а не из-за занятого архивного файла или ошибки записи в PDM.

Старый параметр замены оставлен в ключах совместимости задачи, но не влияет на поведение.
В интерфейсе сообщается, что существующий PDF всегда обновляется новой версией.

Сборка 1.0.2.0 и сценарные проверки выполнены с .NET Framework 4.8 и Ghostscript.
Запуск с реальным SOLIDWORKS PDM/AutoCAD на Windows остаётся обязательной приёмкой.

Здесь «разрегистрация» означает check-out, а «регистрация» — check-in. Файл не удаляется
из базы; его ID и история версий сохраняются. Справка PDM 2018:
https://help.solidworks.com/2018/english/enterprisepdm/fileexplorer/t_Check_Out_Files.htm
https://help.solidworks.com/2018/english/enterprisepdm/admin/IDD_DLG_UNLOCKFILE.htm
